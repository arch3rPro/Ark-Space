# Three-axis workbench for Provider setup

- **Status:** accepted; implemented in the 0.1.3 release candidate with synthetic Linux qualification; human UX acceptance pending
- **Class:** security and interaction
- **Supersedes:** the setup interaction contract in [ADR 0016](0016-tui-provider-setup.md); retained security, language, storage, routing, and ownership protections remain in force

## Context and decision

The earlier six-destination/sidebar and global four-region Tab model was rejected. This decision records the approved replacement contract, not proof that the implementation or usability tests satisfy it.

The workbench has three independent axes:

1. **Top context strip:** Exa, Tavily, Firecrawl, and SearXNG. Switching provider changes context only; it does not enable the provider, change routing, or send a request.
2. **Left functional menu:** Providers, Configuration, Settings, Exit. These are functions, not provider destinations. Search order and setup language are global, not duplicated per provider.
3. **Right content:** resources for the selected provider, or global order/language content. Editing replaces the right content with a form while preserving the top and menu context.

The primary focus model cycles only among Top, Menu, and Content with Tab/Shift+Tab; there is no nested button-bar subfocus. Top contains Exa, Tavily, Firecrawl, and SearXNG. Top Left/Right switches provider; `[` and `]` remain advertised alternate keys, and Down/Enter enters Content. Menu Up/Down selects Providers, Configuration, Settings, or Exit; Enter opens the function and Right enters Content. Content Left moves to Menu. The primary resource table/list drives page-local actions; non-focusable key hints wrap below the table. This is an ArkSpace adaptation, not pixel-identical reproduction of the reference. Enter/`e` edits, `a` adds, `i` shows details, `p` opens secure preview, and `d` removes. Space toggles selected-key enablement in Content; `V`/`v` toggles provider enablement from Top, Menu, or Content while the Providers page is open; `t` opens a Cancel-default chooser for a Provider pool test or sequential tests of all configured local key references; it does not test only the selected row. Global order and language remain independent: `u`/`d` reorder, Delete removes, `I` includes with confirmation, Ctrl-S saves; language is a plain option list applied with Enter. Provider context changes do not change global order/language.

The provider strip renders all labels as `[Name]` with constant brackets, three-space gaps, classic centered placement, and distinct provider accents. No-color rendering remains supported. This presentation does not introduce a new backend.

## Resource editing contract

The user approved reference-first editing: Enter or `e` on an editable resource opens its form in the right content pane. Read-only resources refuse editing with a reason. `i` refreshes the setup snapshot before reading detail fields and refuses to show details if the selected reference changed during refresh. Details include selected-key source (local, environment, or environment override), disabled state, health-failure reason, and remaining cooldown snapshot (not a live countdown while the modal is open). Shared-provider status is explicit. Resource summaries show counts by kind and actionable cleanup guidance; they never expose authority-bearing URLs or secrets. `p` opens the existing read-only credential preview. Empty lists offer Add rather than importing unrelated configuration.

Within a form, selecting a field and pressing Enter starts editing. Enter again commits only to the in-memory draft; it does not write a file. Esc restores that field's pre-edit value. Ctrl-S validates the whole form and enters the normal save/confirmation path. Explicit Save and Cancel controls remain available. An unchanged save closes without writing or requesting replacement consent; a dirty form's cancel/discard confirmation defaults to Cancel. Context/global shortcuts are suppressed in fields and overlays; `[`, `]`, `?`, `q`, and `y/n` are ordinary entered text while editing. Input remains masked with live grapheme count and caret. Editing an existing local key preloads its stored value into the masked field; it is never automatically disclosed as plaintext. Environment-managed, shared, owned, missing, or invalid references remain guarded and unchanged; adding a key starts blank. A changed local key is replaced only through the validated Ctrl-S save and explicit overwrite confirmation.

Action confirmations are explicit controls, initially focused on Cancel. Enter activates only the focused action; Esc cancels. Existing action-specific ownership, routing, replacement, private-CIDR, and network-consent guards remain in force. Root exit defaults to Cancel; Ctrl-C retains its existing direct-cancel behavior. Preview is read-only, masked by default, explicitly revealable only in the owned human TTY, and cleared on exit. Busy operations retain cancellation and cleanup semantics.

## Retained system contracts

- Provider context changes do not enable a Provider, change automatic order, or initiate network activity.
- Search order and language are global. Order edits remain a draft with explicit save/cancel; routing-sensitive confirmation occurs only when required.
- Credentials remain in the trusted local terminal, never Agent chat or command arguments. Environment precedence, reference unlink semantics, and raw-secret exclusion remain unchanged.
- Shared credential references and tracked Browser, Monitor, and Site Monitor ownership guards remain enforced. Disabling a Provider does not remove cleanup access.
- SearXNG remains keyless; environment-only endpoints remain read-only. URL validation and explicit narrow per-instance CIDR consent remain required; no per-instance enable toggle is introduced.
- Opening setup does not authorize network activity. A live connection test requires explicit consent and retains strict selected-Provider routing and existing request limits.
- Cancellation, terminal restoration, validation, and backend mutation guards are unchanged. This interaction decision does not alter Protocol v1, provider execution, or release/version metadata.

## Reference and implementation evidence

The read-only reference is cc-switch CLI, https://github.com/SaladDay/cc-switch-cli, revision `b563ce17fdcc5316701ee8ba00368bdeb24b929a`, MIT. It informed layout and interaction patterns only; its source and assets are not imported. Provenance is recorded in [NOTICE.md](../../../NOTICE.md). Its domain-specific types and operations are not ArkSpace contracts.

Global order and language remain independent functions: order uses `u`/`d` to reorder, Delete to remove, `I` to include with confirmation, and Ctrl-S to save; language is a plain list selected with Enter. On the Providers page, `V`/`v` toggles provider enablement from any browse pane and `t` opens a Cancel-default chooser: one pool test (round-robin, at most five seconds total) or all configured local key references individually. The pool test retains normal shared rotation and health behavior. The all-keys mode uses fixed public query `Agent Skills documentation`, sequentially tests at most one request per configured UI key reference (at most five seconds per key), performs no key/provider fallback, and does not mutate global cursor, health, or configuration. It includes references for disabled or cooling keys when the Provider is enabled; missing/unusable values are skipped without a request. It requires consent covering possible API fees and request logging. Diagnostics use isolated temporary state with restrictive directory permissions and cleanup; progress is sequential, and Esc stops the run with partial outcomes. Details show current reference diagnostics, completed count, and recent results for the current session only; switching provider context does not discard these results. Cached rows are historical, not validation of the currently effective credential. Per-attempt timestamps and durations are numeric. History is memory-only, never persisted or treated as global health, cursor, or configuration. Read-only navigation, preview, and details refreshes retain history; removed references are pruned, and an attempted managed write (including other configuration operations) or normal pool test clears it conservatively. Editing or removing a credential invalidates the affected diagnostic. The cache stores no credential values or fingerprints, so externally changed credential values cannot be detected or reliably invalidate history. Results show only references and classified outcome (succeeded, failed, unavailable, cancelled, or not tested), never payloads, authority-bearing URLs, or secrets. SearXNG remains keyless and retains its existing instance-pool test, not this per-key mode. Editing, overlays and busy operations retain input ownership, so these keys cannot activate a provider change behind them. Existing form drafting, credential protection, confirmation, ownership, network-consent, cancellation, and terminal-restoration contracts remain in force. Linux PTY qualification uses standard-library Python 3 as a development-only prerequisite; it is not an end-user CLI dependency. Automated results are implementation evidence, not human UX acceptance. Human usability, real-service behavior, and Windows/macOS terminal qualification remain unclaimed. The TUI is included in the explicitly prepared `0.1.3` release candidate, not a confirmed published release. Current qualification evidence and caveats are recorded in [the priority-one workbench report](../../../.scratch/setup-priority-one/report.md); final candidate verification and publication blockers are recorded in [release notes](../../../release/0.1.3.md).
