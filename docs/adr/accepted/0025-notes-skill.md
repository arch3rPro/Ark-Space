# Notes Skill

- **Status:** accepted
- **Class:** Skill boundary

Canonical guidance lives at `skills/notes/SKILL.md`. It owns the finished form of a note: template selection, target-neutral frontmatter, retrieval-friendly layout, evidence-state writing, and a lint check before delivery. Explicit invocation and implicit selection are supported, for example when a user asks to turn research results into a note, a knowledge-base entry, or an update to an existing note.

The Skill is upstream- and downstream-neutral. Evidence may come from `web`, `research`, `gh-repo`, supplied material, or any other tool; the Skill only requires that each fact carry a source and a date. The delivery target may be a local directory, an Obsidian vault, WeKnora, or another knowledge base. The Skill does not implement import, does not assume the target provides a Wiki or graph, and skips linking and index updates when the target does not support them rather than simulating them. Searching sources stays with `web`, synthesized reports with `research`, and WeKnora import with `weknora`.

This is a guidance Skill with one Skill-local script. `scripts/lint-note.mjs` is self-contained Node.js 20+ with no dependencies, no `arks` capability, no sibling Skill, no network, no credentials, and no persistent state. Only the lint step needs Node.js; drafting and delivery do not. No existing Skill is changed to depend on `notes`; the canonical plugin directory discovers it directly and version metadata is unchanged.

Notes use a generic frontmatter subset (`title`, `type`, `lang`, `aliases`, `tags`, `sources`, `retrieved`, `version`, `status`, `updated`) that any target can map to tags, metadata, or properties. The default language is Chinese with English proper names, commands, and API names preserved; `lang: en` selects an English note and English section headings. Each H2 section is self-contained so chunked retrieval stays interpretable, and a plain-language summary (`摘要` / `Summary`) follows the title.

A note is a complete record the reader can act on without reopening the sources. For a tool survey that means what it is and what problem it solves, how it works, full installation, a worked tutorial, configuration and commands, features, comparison with comparable tools, and limits that affect adoption. Length follows completeness; long sections are split by subtopic for retrieval rather than shortened.

Evidence has two states. A verified statement is direct, with sources listed in the Sources section. An inferred statement is marked once, inline, with its basis. There is no closing "to confirm" section: a fact that can be looked up is looked up, an unsupported fact is left out, and a gap that changes the reader's decision is stated in one sentence where it matters. When the evidence does not cover a section the note needs, the Skill returns to the evidence tools or tells the user what is missing; it does not shape or limit upstream research. Hedging in the body is a lint warning.

The lint script checks required frontmatter and enumerated values, Summary and Sources presence, `verified` status without `retrieved`, heading levels, H2 length (a retrieval-splitting hint, not a size limit), context-dependent H2 openings, hedge density, and, only when `--root <dir>` is supplied, broken `[[links]]`. Errors set exit code 1; warnings do not. Stdout is text or `--json`, and diagnostics go to stderr. Code blocks, inline code, and block quotes are exempt from hedge detection. The hedge lexicon merges three layers in order: built-in `lexicons/{zh,en}.json`, repeatable `--lexicon <file>`, and an optional `.notes-lint.json` in the note's own directory (no upward search). Each layer has `hedges` and `allow` lists.

A mandatory Skill-owned storage layer or Wiki maintenance script would couple the Skill to particular targets and break the neutral boundary. Per-type Skills would multiply activation surfaces; additional templates are added only for a concrete use. Lint results are advisory evidence about form, not proof that a note is factually correct, and the Chinese lexicon's false-positive rate has not been measured.
