## Executive comparison

Exa is a small, provider-specific Skill catalog: five canonical `SKILL.md` files, one reference library under `build-with-exa`, direct HTTP/SDK/MCP setup instructions, and installation through `npx skills add` ([catalog and install](https://github.com/exa-labs/agent-skills/blob/14714fdc8d322e24cfc347a912407c4a1d962e16/README.md#L12-L26), [reference index](https://github.com/exa-labs/agent-skills/blob/14714fdc8d322e24cfc347a912407c4a1d962e16/skills/build-with-exa/SKILL.md#L150-L165)). ArkSpace is deliberately broader: four outcome/lifecycle Skills sit above a provider-neutral `arks` boundary, with credentials, fallback, owned state, machine contracts, tests, and native plugin metadata centralized in the repository.

The most reusable Exa pattern is not its provider-shaped catalog or credential setup. It is the combination of [explicit activation and routing](https://github.com/exa-labs/agent-skills/blob/14714fdc8d322e24cfc347a912407c4a1d962e16/skills/company-research/SKILL.md#L1-L24), [terse pitfalls](https://github.com/exa-labs/agent-skills/blob/14714fdc8d322e24cfc347a912407c4a1d962e16/skills/exa-search/SKILL.md#L277-L287), and [progressive disclosure](https://github.com/exa-labs/agent-skills/blob/14714fdc8d322e24cfc347a912407c4a1d962e16/skills/build-with-exa/SKILL.md#L150-L165) into focused references.

## Prioritized recommendations

1. **P0 — Preserve ArkSpace's outcome/lifecycle boundaries and `arks` machine protocol.** Do not reproduce Exa's [provider/API-shaped top-level catalog](https://github.com/exa-labs/agent-skills/blob/14714fdc8d322e24cfc347a912407c4a1d962e16/README.md#L12-L20). Put any Exa-specific corrections behind the existing `web`/`research` operation references or provider adapters, consistent with `AGENTS.md` and [`docs/architecture.md`](../architecture.md).
2. **P0 — Retain the human credential boundary and consent rules.** Do not copy Exa's [API-key MCP-header example](https://github.com/exa-labs/agent-skills/blob/14714fdc8d322e24cfc347a912407c4a1d962e16/skills/lead-generation/SKILL.md#L166-L181) or [unpinned SDK installation](https://github.com/exa-labs/agent-skills/blob/14714fdc8d322e24cfc347a912407c4a1d962e16/skills/build-with-exa/SKILL.md#L24-L42) into Agent-managed setup. Keep `arks setup`, credential references, minimal subprocess environments, and `arks doctor` as the supported path ([INSTALL](../../INSTALL.md)).
3. **P1 — Apply Exa's concise routing style within existing Skills.** Following its [“two surfaces, two jobs” example](https://github.com/exa-labs/agent-skills/blob/14714fdc8d322e24cfc347a912407c4a1d962e16/skills/company-research/SKILL.md#L9-L24), give each ambiguous branch a short “operation A for X; operation B for Y; do not use Z” block, followed by explicit result fields and terminal conditions. This improves selection without adding a registry or extension point.
4. **P1 — Expand progressive-disclosure references only where a concrete operation needs them.** Adapt Exa's [recommended-request and pitfall presentation](https://github.com/exa-labs/agent-skills/blob/14714fdc8d322e24cfc347a912407c4a1d962e16/skills/build-with-exa/SKILL.md#L44-L62) into the owning `skills/web/references/*.md` or `research` reference when recurring failures justify it. Keep Provider wire shapes in `src/providers/`, Protocol schemas, or Provider-specific reference material—not in canonical activation prose.
5. **P1 — Automate the verification already promised by `docs/adding-skills.md`.** Add table-driven positive/negative activation fixtures and an isolated installed-Skill smoke test that invokes the documented `arks` entry path. Keep existing frontmatter, link, plugin, package-content, and real-entry tests.
6. **P2 — Defer a developer-facing “build with ArkSpace” Skill.** Exa's [`build-with-exa` developer guide](https://github.com/exa-labs/agent-skills/blob/14714fdc8d322e24cfc347a912407c4a1d962e16/skills/build-with-exa/SKILL.md#L10-L24) is useful for its API platform, but ArkSpace already has architecture, protocol schemas, and CLI documentation. Add such a Skill only when a concrete host workflow needs activation-time implementation guidance; otherwise it would duplicate reference documentation and violate the no-speculative-framework rule.

## Bottom line

Exa's repository is a lightweight [five-Skill catalog](https://github.com/exa-labs/agent-skills/blob/14714fdc8d322e24cfc347a912407c4a1d962e16/README.md#L12-L20) with concrete [routing](https://github.com/exa-labs/agent-skills/blob/14714fdc8d322e24cfc347a912407c4a1d962e16/skills/company-research/SKILL.md#L9-L24), [pitfall](https://github.com/exa-labs/agent-skills/blob/14714fdc8d322e24cfc347a912407c4a1d962e16/skills/exa-search/SKILL.md#L277-L287), and [result-use](https://github.com/exa-labs/agent-skills/blob/14714fdc8d322e24cfc347a912407c4a1d962e16/skills/lead-generation/SKILL.md#L127-L145) patterns. ArkSpace should borrow those presentation techniques while retaining its stronger provider-neutral contracts, credential isolation, lifecycle semantics, validation, and canonical-source packaging.
