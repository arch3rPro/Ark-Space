# ArkSpace Setup TUI：交互重设计草案

Status: awaiting-review

本轮只做走查与设计。此文件不授权修改实现、依赖、版本、全局安装或真实配置。已有未提交代码保持不变；新增的只是这份设计稿。

## 1. 目标与完成语义

目标不是极致简单，而是可识别的布局、稳定的导航、明确的对象操作和完整的状态反馈。用户不需要读一段解释才能找到操作。

- 首页有设计和视觉层次，但不展示统计卡片或密钥健康报表。
- Provider、Key/实例、全局设置的责任不混杂。
- 添加、编辑、删除在当前工作区完成，不层层进入问答菜单。
- 所有确认统一 `[y/N]`，默认拒绝；中文界面也不要求输入中文。
- 语言只在全局导航出现一次。直接 Provider 入口仍使用同一个外壳。
- 操作对象始终明确；外部凭据、资源所有权、权限和部分写入不能为简洁而隐藏安全事实。

## 2. 当前界面的测试证据

使用已有 `dist/cli/main.js`，真实 Linux PTY、独立临时 `ARKSPACE_HOME`、合成凭据。无真实 API 搜索，没有修改源码、构建、安装或真实用户配置；临时目录和进程已清理。

| 严重度 | 已观察的问题 | 证据与影响 |
| --- | --- | --- |
| P1 | 全局语言重复进入 Provider 页面 | 首页和 Exa 页面均显示语言；用户无法建立全局/局部的区分 |
| P1 | 空配置显示假密钥条目 | 首页 `0 configured`，Provider 却显示 `Key #1 — missing, unavailable, enabled` |
| P1 | 密钥操作充满内部字段 | 常规页显示匿名哈希 ID 和资源数量，不服务于添加/编辑任务 |
| P1 | 多位编号会进入错误操作 | 12 个密钥的页面显示编号 10，输入 `10` 却立即打开编号 1 的添加表单 |
| P1 | 小窗口会超过视口 | 24 列 × 8 行，环境密钥操作页实际发送 18 行布局，关键内容无法同时呈现 |
| P2 | 返回不保留焦点 | 从 SearXNG 返回，首页选中项回到 Exa |
| P2 | 入口改变返回语义 | `setup exa` 按 Esc 退出进程，而不是回到全局设置 |
| P2 | 确认是另一套输入模式 | 英文 `y` 单独输入不执行，还需 Enter；中文显示 `[y/是/确认，默认否]` |
| P2 | 大列表没有分页操作 | 60 × 12 窗口下 PageDown 不改变选择 |
| P2 | 标签承担说明书 | 动作包含连续输入、确认、顺序影响等多种括号解释 |

证据纪律：两次初始走查脚本因假设条目编号固定/等待屏外标签而中断；修正测试定位后核对对应场景，不把这些脚本问题当作产品故障，也不宣称整套可用性验收已通过。子代理提出的“最后一页只剩一个条目”假设经实际走查未复现（观察到 7 个可见条目），不列入问题清单。表单缩放、Unicode 字宽、错误长期可见性还有源码层面风险，尚未实测，不冒充已复现。

## 4. 信息架构

一个持久工作区：应用标题、全局侧栏、主内容、局部操作栏、状态区、快捷键栏。不是每个选择都打开一个新页面。

- 全局侧栏：Exa、Tavily、Firecrawl、SearXNG；搜索顺序；语言。
- Provider 主内容：Provider 开关、真实密钥/实例列表、选中对象信息、对象操作、测试连接。
- 模态层：新增、替换、实例编辑、删除确认、联网/权限确认。
- 诊断：出错时在局部状态区呈现；内部 anonymous ID、资源生命周期细节不常驻首页。

首页即这个工作区，不额外插入“欢迎/请选择”页面。默认打开 Exa；`setup searxng` 打开同一外壳并选中 SearXNG。会话内记住每个 Provider 的选中对象和滚动位置，不为了这个功能新增持久 UI 状态。

## 5. 页面与状态

线框图表达区域关系，不是最终像素/字符宽度验收；实际渲染必须按终端单元格处理中文、组合字符与宽字符。

### A. 常规 Provider 工作区

```text
┌─ ArkSpace 设置 ──────────────────────────────────────┐
│ PROVIDERS      │ Exa                                 │
│                │ Provider                  [已启用] │
│ › Exa          │                                    │
│   Tavily       │ API 密钥                            │
│   Firecrawl    │ ┌────────────────────────────────┐ │
│   SearXNG      │ │ › EXA_API_KEY       本地 · 启用  │ │
│                │ │   EXA_API_KEY_2     环境 · 启用  │ │
│ 设置           │ └────────────────────────────────┘ │
│   搜索顺序     │                                    │
│   语言         │ [添加] [替换] [停用] [删除]        │
│                │                    [测试连接]      │
├─────────────────────────────────────────────────────┤
│ 已保存                                              │
│ Tab 切换区域 · 方向键选择 · Enter 操作 · Esc 返回     │
└─────────────────────────────────────────────────────┘
```

Provider 启停与密钥启停是不同控件：前者在标题区域并明确标注 Provider，后者是选中密钥的动作。密钥行显示稳定引用名、来源、状态，绝不显示值或尾号。默认未填的占位引用不成为假条目；用户显式登记但缺值的引用保留并标为缺失，可取消引用。

环境凭据的替换按钮不可用；焦点经过按钮时，状态区说明“由环境变量管理”，而不是常驻大段警告。资源归属阻止的操作，执行前/执行失败时明确反馈，不静默隐藏限制。

### B. 空状态

```text
Exa                                      [已启用]

API 密钥
┌─────────────────────────────────────────────┐
│ 尚未添加密钥                                │
│                 [添加密钥]                  │
└─────────────────────────────────────────────┘
```

进入空 Provider 时，内容焦点默认落在添加按钮。没有假密钥、缺失/可用/启用三套冲突状态。测试连接在不可执行时禁用，焦点提示缺少凭据；仍可管理显式外部引用。

### C. 新增/替换密钥弹窗

```text
┌─ 添加 Exa 密钥 ─────────────────────────────┐
│ API 密钥                                   │
│ [                                        ] │
│                                            │
│ 获取密钥：dashboard.exa.ai/api-keys         │
│ 明文保存于：…/arkspace/credentials.json     │
│                                            │
│                    [取消]  [保存]          │
└────────────────────────────────────────────┘
```

输入隐藏，UI 不表示真实长度；无值/尾号出现在屏幕、状态区、日志或录制中。按保存后回到原列表并选中新对象。采用“一次弹窗保存一个密钥”；想再添加直接按添加，不让用户落进不知何时结束的循环。替换使用相同表单，明确显示目标引用；提交时显示覆盖确认。未提交草稿不写磁盘，Esc 丢弃草稿。

成功后不另开完成页，状态区显示“已添加”。失败保留表单和输入焦点，但秘密不回显；可重试/取消。部分写入必须区分“未保存”与“凭据已保存但注册失败”，给出可滚动恢复诊断，不说已回滚。

### D. 删除确认

```text
┌─ 删除密钥 ─────────────────────────────────┐
│ Exa / EXA_API_KEY                          │
│                                            │
│ 删除此密钥？ [y/N]                         │
└────────────────────────────────────────────┘
```

对象、影响、默认拒绝三个信息足够。共享/环境引用改变实际影响时，替换为准确提示，例如“取消此环境变量引用？环境变量不会删除。”

`y/Y` 确认，`n/N`、Esc 取消；默认焦点在 N，Enter 默认取消。若用户明确把焦点移动到 Y 按钮，Enter 执行该按钮，而不是反向取消。单键完成，不切到 readline 问答。确认只作用于弹窗打开时绑定的稳定对象，不按当前行号重新解析。

### E. SearXNG 实例编辑

```text
┌─ 编辑实例 ─────────────────────────────────┐
│ URL                                       │
│ [https://search.example/                 ] │
│                                            │
│ 网络权限                                  │
│ [公共网络 ▾]                              │
│                                            │
│                    [取消]  [保存]          │
└────────────────────────────────────────────┘
```

Provider 页面不同时塞普通添加/高级添加两个几乎相同动作。新建与编辑用同一表单；网络权限进入局部编辑，手动 CIDR 只在这里展示。私网访问需窄范围显式授权，公共实例不反复询问。规范化 URL 不变保留权限；端点身份改变不继承旧权限。追加不会重新启用已有被停用的 Provider；首次本地配置按现有后端默认启用创建，但不插入自动顺序。

SearXNG 的实例操作仅有添加、编辑、删除，不展示后端不存在的单实例启停。启停属于整个 Provider。环境-only SearXNG 只显示一个当前有效端点，不能在本地编辑、删除或启停；与环境密钥的“可取消引用”规则不同。显式新增本地配置后，本地实例覆盖环境端点，不混合轮询。删除最后本地实例后按后端规则移出自动顺序；若环境端点仍存在，可重新成为有效来源。

### F. 搜索顺序与语言

搜索顺序是单独内容页：显示实际顺序；选中 Provider 后有上移、下移、移除、添加动作，直接更新本地草稿。统一保存/取消，避免每移动一次都弹确认。切换到其他内容再返回时保留会话草稿与选中项，不静默丢失；只有明确保存或取消才清除草稿更改。保存一次性预览实际新旧顺序；涉及 SearXNG/托管路由隐私变化时进行一次确认。至少保留一个 Provider。启用状态单独标示，不把顺序当启用开关。

语言页只有 English/中文两项，当前项标记选中，Enter 应用并保存偏好；保留工作区焦点，切换不改查询语言、不联网。页面仅由全局导航访问，不在 Provider 重复入口。已有 `--lang` 临时初始覆盖语义保留。

### G. 测试、错误与部分保存

- 测试连接先显示选定 Provider、固定测试查询、费用/日志影响，`[y/N]` 授权。
- 执行中状态区显示进行中，禁止重复提交；取消请求走现有取消机制，不把停止等待当成服务成功或清理完成。
- 结果说明成功/失败与实际尝试，不能把单次成功写成“所有密钥有效”。详细尝试记录可展开，不淹没常规配置页。
- 输入校验错误在对应字段下呈现，焦点保留；安全/所有权错误在弹窗内显示。
- 长错误可滚动，恢复命令不能截断；错误直到修正、取消或明确关闭才消失。

## 6. 输入与焦点契约

| 场景 | 行为 |
| --- | --- |
| Tab / Shift-Tab | 循环切换导航、列表、对象动作、Provider 控件；弹窗打开时焦点困在弹窗 |
| 方向键 | 在当前区域选择；按钮行使用左右，列表使用上下 |
| Enter | 对当前焦点执行；文本字段提交由清楚的保存控件/表单语义决定，不隐式提交非相关对象 |
| Esc | 弹窗取消并返回触发对象；内容焦点退回侧栏；侧栏再返回/退出根工作区 |
| Ctrl-C | 退出，恢复终端；保留之前已提交操作，不提交当前草稿 |
| PageUp/PageDown、Home/End | 列表分页、首尾；不能显示虚假的多位编号快捷键 |
| y/N | 仅在确认弹窗生效，普通文本/秘密字段的 y 是输入内容 |
| a/e/d | 列表焦点下添加/替换或编辑/删除的加速键；不是唯一操作路径，在文本字段中不拦截 |

选中使用稳定引用/规范 URL，不使用行号。删除后选相邻对象；新增后选新对象；取消回原对象；对象被并发移除则刷新并给出明确提示，不落到另一个对象上继续操作。

Esc 根工作区的退出行为需与弹窗取消一致：无未保存草稿可直接退出；存在草稿不能静默保存。只有会丢失实质更改的编辑需要放弃确认，不为每次 Esc 增加确认。

## 7. 视觉与窗口规则

- 区域标题与内容边框有层次；焦点区域边框/标题加强，选中行有反色/标记；禁用动作弱化；成功、警告、错误有不同状态样式。
- 默认跟随终端背景，不强制黑底；用终端语义色：焦点 cyan/accent、成功 green、警告 yellow、错误 red、禁用 dim。选中行反色；模态框使背景工作区弱化，输入焦点和默认拒绝状态明显。实际颜色对比需在深/浅主题验收。
- 颜色不能是唯一语义；黑白终端仍依靠文字、焦点标记和边框判断状态。
- 不做统计卡片，不默认显示说明书，不复制 K9s 的监控首页。列表是资源选择器，不是后台统计表。
- 常规 80×24 及以上为侧栏布局。60×16 到低于 80 列采用单列紧凑布局，保留导航位置、全局入口、上下文标题和同一弹窗模型；不是另一套问答工具。
- 小于 60×16 显示可读的“窗口过小，请扩大终端”，只保留返回/退出；不允许关键确认或保存按钮被挤出屏幕。阈值属于待原型验证的提案，不是已验证能力。
- 调整窗口保留草稿、焦点和选中身份；表单、确认、错误与列表全部重新布局。
- 长引用和 URL 用明确省略号；选中对象能展开完整信息。内容可滚动，状态与快捷键区保持可见。
- 按终端单元格渲染，覆盖中文、组合字符、宽字符；不依赖简单字符串长度或“非 ASCII 都算两个字符”的启发式。

## 8. 安全及非目标

复用现有配置、凭据和状态契约；外部值优先、共享引用与拥有资源的保护、手工禁用保护、CIDR 隔离、显式联网、秘密错误体清洗和部分写入诊断不削弱。UI 草稿与已保存对象分离，但多文件写入仍不是全有或全无事务，界面必须诚实呈现。

不增加健康仪表盘、插件系统、持久导航框架、用户角色、命令面板或新凭据格式。实现库选型留到设计通过之后；不为了零依赖继续堆半套交互，也不为了漂亮引入不必要的框架。没有批准发布、安装或版本变化。

## 9. 下一阶段验收矩阵

实现须得到批准后才开始。以下是验收要求，不是本轮通过的测试。

1. 空配置：首屏清楚看到添加入口，零假密钥；Provider 进入与添加只需两次激活，不经过额外 Manage 菜单。
2. 双语：语言只在全局一处；相同布局、相同 `[y/N]`；中文/英文标签不溢出。
3. 12/50 个密钥：身份/顺序正确、分页/首尾有效、无编号误激活；取消/返回保留选择。
4. 新增/替换/删除：弹窗内完成；草稿取消不写；成功选择正确对象；秘密不出现于 stdout/stderr/状态/录制。
5. 环境/共享/拥有资源：限制可发现、行为真实；不能绕过后端保护。
6. URL/CIDR：无效输入保留焦点；公共、私有字面 IP、私有 DNS 授权明确，权限不跨实例继承。
7. 搜索顺序：多次调整只提交一次；取消草稿不写；涉及隐私的保存确认一次，空顺序拒绝。
8. 网络：未授权零请求；执行中不重复提交；取消/超时/失败/部分输出分开，不暴露响应秘密。
9. 窗口：120×30、80×24、60×16、24×8；页面/表单/确认/长错误切换和缩放，按声明布局或过小保护，不滚掉危险确认。
10. 生命周期：正常退出、Esc、Ctrl-C、EOF、渲染错误、IO 错误均恢复 raw mode、光标与原屏；无残余监听器。
11. 并发：对象失效时刷新并告知，绝不把修改误施于当前相同行号的另一个对象。
