## 后端依据（只读）

- `src/config/schema.ts`：`SearxngInstanceSchema` 只有 URL/CIDR，没有单实例 enabled；URL 限长、拒绝控制字符/空白/反斜线，规范化尾部斜线；`getSearxngConfig` 优先本地配置，否则使用唯一有效环境 URL。
- `src/config/manage.ts`：环境-only SearXNG 没有可本地编辑/删除的实例；删除最后本地实例移除自动顺序中的 SearXNG；不能让顺序为空。
- 现有追加行为：已有本地 Provider 停用状态保留；首次本地配置按默认启用创建，不自动加入顺序。

## 发现与修订

| 问题 | 验证/依据 | 本轮原型修订 |
| --- | --- | --- |
| 顺序草稿跨页丢失 | 模型回到 order 时重新从已保存 order 初始化；新增用例失败 | 会话草稿及有效选中项保留，只有明确保存/取消改变提交状态 |
| 环境-only SX 像密钥一样可删除 | 通用 environment guard 仅挡替换，fixture 还伪造两个环境实例；新增用例失败 | 只显示一个有效环境端点，实例编辑/删除/独立开关只读 |
| 提供不存在的单实例启停 | 后端实例 schema 无此字段；新增用例失败 | SX 对象操作只保留添加、编辑、删除；启停属于 Provider |
| 本地与环境实例混合 | 保存只 append，没有按本地配置优先解析；新增用例失败 | 新本地配置覆盖有效环境列表；保留独立 fallback 元数据，最后本地实例删除后可恢复 |
| 无本地配置却可启用 SX | 空态 toggle 制造一个后端不存在的配置开关；新增用例失败 | 空态开关禁用并提示先添加；首次创建默认启用，已存在被停用的配置追加不重启 |
| URL 校验被标准解析器放宽 | `new URL` 可接收后端拒绝的空白等输入 | 限长并拒绝空白/控制/反斜线；规范化身份，避免尾斜线重复 |
| 仅改变尾斜线却清空授权 | 按原始文本判断端点改变；新增规范身份用例 | canonical identity 不变保留权限，真正端点改变才清除，UI 与模型保持一致 |

其余保护仍存在：环境 Key 可取消引用但不可替换；共享引用可取消但不可覆盖；拥有资源阻止替换/删除/整个 Provider 停用，单 Key 停用保留清理引用。SearXNG 无密钥，模拟配置失败不会生成假凭据 orphan。
