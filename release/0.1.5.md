# ArkSpace 0.1.5 release candidate

This candidate includes changes since 0.1.4. CLI, MCP, package/lockfile, and versioned plugin metadata are aligned at `0.1.5`. It has not been published to npm; README installation commands continue to use `@latest`.

## Highlights

- **Manual npm CLI updates:** `arks update --check` checks the official stable npm release without configuration/credential bootstrap or npm execution. `arks update` displays the verified npm-global target and asks `[y/N]`, case-insensitively. Empty input, EOF, and non-interactive input never approve installation; there is no `--confirm` bypass. Equal versions are not reinstalled and newer local versions are not downgraded. Source, linked, local, and mismatched installations cannot self-update.
- **Bounded, consented installation:** install the checked version at the verified prefix using the current Node and npm JS entry, without shell/sudo or lifecycle scripts. Engine and TLS checks remain enabled. JSON stdout contains one updater result; prompts/progress stay on stderr. Cancellation awaits the owned npm child, while failed/interrupted installs honestly report possible partial changes rather than promising rollback. Separately installed Skills and host registrations are untouched; files bundled in the npm package change with it. See [ADR 0020](../docs/adr/accepted/0020-manual-npm-cli-update.md).
- **Research evidence review:** independently read original sources for consequential claims, track gaps and claim-to-source support, and distinguish source-level evidence from verified passages. A normal review is one pass with at most five extra capability calls, including failures/cache reads; wider work needs consent. Paid Research Jobs are not resubmitted by default. Research and Web guidance also reject instructions embedded in retrieved source content. This is host guidance, not a new research backend or evidence guarantee.
- **Skill and Codex metadata:** six Skill-local icons, notices, display names, short descriptions, and default prompts; Browser and Monitor remain manual-only, while the other four Skills permit implicit invocation. Codex metadata uses a local marketplace source, the ArkSpace icon, repository/website links, and concrete capability labels while preserving the original introduction.
- **Installation guidance:** English/Chinese READMEs use `@latest` and document separate `npx skills@latest check` / `update` commands. Native plugins continue through their host's plugin manager.
- **Setup workbench rebuild (pi-tui engine):** the interactive `arks setup` surface was rewritten on a differential-rendering engine (exact-pinned dependency, no per-frame screen clearing) behind a pure reducer core: six Top-strip contexts (Exa, Tavily, Firecrawl, SearXNG, WeKnora, UseGPT) with `arks setup <context>` deep links, masked secret entry with cancel-default consents on every destructive or billable action, per-key and pool test flows with live progress and Esc cancellation, per-instance private-CIDR authorization for SearXNG, WeKnora connection editing with consented live verify, UseGPT service start/stop/diagnose plus offline Tunnel ID/data-directory/key/unlink management, draft provider ordering, and guaranteed terminal restoration. Non-TTY machine output is unchanged (one plain line, never the alternate screen). **Breaking:** the CLI now requires Node `>=22.19.0`, and the previous workbench and its `ARKS_TUI` escape hatch are removed — there is no fallback TUI. See [ADR 0023](../docs/adr/accepted/0023-pi-tui-setup-engine.md) and [ADR 0024](../docs/adr/accepted/0024-workbench-presentation-contract.md); retained interaction and security contracts remain in [ADR 0016](../docs/adr/accepted/0016-tui-provider-setup.md) and [ADR 0017](../docs/adr/accepted/0017-workbench-modal-setup.md).

## Verification evidence

- `npm run check`: **567 tests across 55 files** passed, including **45 updater entry tests**. The updater EOF regression first reproduced approval of a buffered Y without Enter; the close-state guard now declines it.
- Updater tests cover intercepted registry/npm boundaries, the exact packed artifact in an isolated prefix, scope refusals, install flags, failure/verification, cancellation, and seven **native Linux PTY** cases (Y/y, N/n, empty, EOF, Ctrl-C) with terminal mode restoration.
- `npm run test:setup`: **72 source and 72 isolated-installed Linux PTY checks** passed against the rebuilt workbench, reconstructed from the differential output stream: key CRUD and consents, masked preview reveal/clear-on-leave, chooser zero-request, per-key and pool test request counts, mid-run Esc partial rows, CIDR grant, ordering persistence, both connection pages, Chinese narrow-screen geometry, and terminal restoration on every exit path. Installation used local runtime tarballs, an owned empty cache, offline npm, and denied lifecycle scripts. Non-TTY output is byte-checked on both entries and leaks no control sequences.
- A live read-only registry check before the version bump returned current/latest `0.1.4` and `up-to-date`; it did not install anything. This is registry connectivity evidence, not an actual update-install test.
- `npm run verify:package`: **326 files**, no runtime install scripts; version metadata alignment and `git diff --check` passed.
- `npm run verify:release` is required on the clean reviewed preparation commit before publication; it validates the exact package artifact and does not publish or tag.

Native Windows/macOS updater and real-TTY qualification, human usability acceptance of the rebuilt Setup workbench, real registry update installation, live host/plugin behavior (including desktop icon theme synchronization), and Provider/research quality tests remain unperformed. Existing CI matrix configuration and synthetic mocks are not evidence that those checks ran. The original 36-character Codex short description remains a narrow validation exception, not proof of submission-limit compliance.

## Installation

Published 0.1.4 lacks `arks update`. Until 0.1.5 is explicitly published, the following installs the currently published stable package, not this candidate:

```bash
npm install --global @arkspace/cli@latest
```

To test the candidate before publication, follow [source development](../INSTALL.md#source-development) and use the local `arkspace-cli-0.1.5.tgz` artifact described there. Obtain consent before replacing a global installation; the artifact's version alone does not prove npm availability.
