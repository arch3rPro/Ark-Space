# ArkSpace 0.2.0

**Released: 2026-11-06.** CLI, MCP, lockfile, and versioned plugin metadata are aligned at `0.2.0`. Publication was separately authorized; the clean-commit release gate passed on preparation commit `65867ea` and is checked again on the final documentation commit. This release does not declare replacement cutover or blanket host/platform acceptance.

The historical npm/source comparison baseline is `0.1.7`. Its recorded `gitHead`, `5d0f5873d9dd4809453449e8ae6a746c11dfaf11`, is an ancestor of 0.2.0. Versions 0.1.6 and 0.1.7 were published to npm without corresponding Git tags or GitHub Release archives found in the historical check; see [0.1.7 historical notes](0.1.7.md).

## Changes since the published baseline

### New and rebuilt workflows

- **UseGPT Artifact Hub:** replace the legacy CDP-oriented path with a local Project / Task / Artifact / Handoff workflow, immutable artifact revisions, native-file publication and verification, daemon/worker execution, and owned Tunnel controls. Setup provides service start, stop, diagnosis, and connection settings. Native CSV/PNG persistence has specific [acceptance evidence](../docs/usegpt-native-file-acceptance.md), not a guarantee for every host, mode, or file format.
- **Notes Skill:** add self-contained guidance for finished, retrievable notes with explicit sources and one local lint script. It does not require the shared CLI or sibling Skills.
- **X through owned Nitter:** add `x.search`, `x.thread`, `x.user`, and `x.timeline` plus the canonical `x-search` Skill and managed Nitter configuration. Calls require confirmation to spend the operator's X session quota, treat returned content as untrusted, and do not silently retry or fall back to another source.
- **Setup workbench:** rebuild on the differential-rendering pi-tui engine with seven service contexts: Exa, Tavily, Firecrawl, SearXNG, WeKnora, UseGPT, and Nitter. The six menu entries are Search, Social media, Knowledge, Tools, Settings, and Exit; search order remains a Search strip tab. Retain masked editing, cancel-default consents, owned-resource guards, key/pool diagnostics, cancellation, and terminal restoration.
- **Credential status:** record when a key was last checked. A timestamp is historical evidence, not a claim that credentials or a remote service are currently usable.

The current inventory contains ten canonical Skills. `askme`, `gh-repo`, the manual CLI updater, and the existing Web/Research/Browser/Monitor capabilities were already present at the published baseline; they are not presented as new 0.2.0 capabilities. See [Roadmap](../ROADMAP.md) for current implementation and remaining acceptance gates.

### Reliability and safety

- Classify X input-file, JSON, request-schema, confirmation, disabled-capability, and response-schema failures with fixed safe reasons. Canonical `arks invoke x.*` argument-parser failures remain inside JSON output and do not echo unknown argument values.
- Make bounded text, array, and quote truncation visible in warnings; preserve validated poll data in tweets and quoted tweets. Unreported statistics are not fabricated as zero.
- Validate pagination types and cursor consistency, preserve opaque cursors without truncation, and accommodate valid cursor/query percent-encoding expansion in the Nitter-only transport path budget.
- Reject credential echoes even when JSON Unicode escapes hide them in raw response text.
- Clarify thread pagination: `repliesOmitted` counts reply threads excluded on the current page by `maxReplies`; the next cursor cannot recover those threads. Raise the limit and reread that page when needed, and merge repeated context by tweet ID.
- Preserve the built CLI entry's executable permissions. Remove project NOTICE bookkeeping and its package requirement while retaining the root MIT `LICENSE` unchanged.

## Upgrade notes

1. **Breaking runtime requirement:** Node.js must be `>=22.19.0`, up from published 0.1.7's `>=20.0.0`. The current CLI uses unflagged `node:sqlite` and the pi-tui dependency. Guidance-only Skills retain their own compatibility declarations.
2. **Setup engine replacement:** the old workbench and `ARKS_TUI` fallback are removed. Update terminal interaction expectations; there is no legacy TUI fallback.
3. **UseGPT workflow replacement:** review the [current Skill](../skills/usegpt/SKILL.md) if you used the old CDP workflow. Do not assume automatic migration of legacy workflow state. This preparation does not change personal configuration, credentials, or running user services.
4. Update separately installed Skills independently of the npm CLI. Native plugins load canonical sources directly and use their host's plugin update mechanism. No generated plugin mirror or plugin compilation step is introduced.
5. Install the release with `npm install --global @arkspace/cli@latest` and verify the installed version with `arks --version` (expected: `0.2.0`). The historical 0.1.7 baseline is for comparison only.

## Remaining qualification limits

- Current tests run locally on Linux; hosted Windows/macOS, architecture and Node-version matrices are not established by CI configuration alone.
- Claude Code/Codex installed-host discovery, human terminal usability, real registry update installation, broader Skill activation, and credentialed Provider/research quality and lifecycle acceptance remain separate gates. No host CLIs are installed as part of this preparation.
- Nitter calls continue to warn when the configured connection uses plaintext HTTP. No endpoint, credential, transport policy, or account-risk setting is silently changed.
- This release does not declare replacement cutover of the existing ArkSpace project. The [cutover gates](../docs/migration.md#cutover-gates) still apply.
- These remaining qualification gates are independent of publication authorization and do not imply cutover or broad acceptance. See [Maintenance](../docs/maintenance.md#release-boundary).
