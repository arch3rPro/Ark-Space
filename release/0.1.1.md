# ArkSpace 0.1.1

ArkSpace 0.1.1 is a preview update focused on credential onboarding, Skill guidance, and installation reliability.

## Included

- Human-controlled `arks setup` with hidden API-key input in an interactive terminal.
- A dedicated user-level `credentials.json` store with owner-only POSIX permissions, atomic writes, and explicit environment-variable precedence.
- Non-interactive setup that initializes configuration without requesting or creating secrets.
- Installation-first English and Chinese README flows plus a repository-owned `INSTALL.md` covering install, verification, update, and uninstall.
- Explicit compatibility declarations and clearer routing, result handling, and structured-extraction bounds for canonical Skills.
- Positive and negative activation fixtures and isolated-Skill validation.
- Installed-host MCP verification that reports malformed protocol output directly.

## Requirements

- Node.js 20 or newer.
- A local filesystem-based Agent host with shell, network, and persistent user storage.
- Applicable Exa, Tavily, or Firecrawl credentials for Provider-backed operations.

Install after npm publication:

```bash
npm install --global @arkspace/cli@0.1.1
arks setup
arks doctor
```

Run `arks setup` yourself in a trusted interactive terminal. The local credential file contains plaintext secrets and is not an operating-system keychain; explicit environment variables remain the higher-priority source for CI and managed environments.

## Preview qualification

This release does not replace or retire the previous ArkSpace repository. Hosted operating-system matrices, exact-published-version host installation, credentialed Provider E2E, and migration cutover validation remain post-release qualification.

## Security

ArkSpace keeps raw keys out of Agent conversations, command arguments, `config.json`, and `state.json`. Browser and Monitor mutations require explicit confirmation, and owned resources remain pinned to the anonymous key identity that created them. Report vulnerabilities according to `SECURITY.md`.
