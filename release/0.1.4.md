# ArkSpace 0.1.4 release candidate

This is a prepared release candidate, not a published release. It adds optional managed WeKnora connection verification and retrieval while retaining the independently usable environment-variable path. The pinned npm install command becomes available only after publication.

## Highlights

- **Optional managed WeKnora access:** configure the API root, masked key, and optional default knowledge-base ID through `arks setup weknora`. Supported operations are connection verification, knowledge-base list/detail, and single-knowledge-base search. WeKnora remains optional: a manually supplied `WEKNORA_BASE_URL` / `WEKNORA_API_KEY` pair works independently without installing `arks`; other operations (imports, document/chunk operations, multi-base search, and streamed chat) continue on that environment path.
- **Bounded and explicit network access:** an explicit request to read the configured instance authorizes the request; there is no separate HTTP confirmation. Valid localhost, private, and public destinations need no CIDR grant. URL/address validation, DNS pinning, TLS verification, redirect refusal, no-proxy transport, deadlines, and response bounds remain in force. HTTP is supported with an informational plaintext-transport warning. Managed WeKnora is not a Web Provider and does not join search order or fallback.
- **Setup usability:** WeKnora edits one selected field at a time, keeps incomplete values in session-only drafts, and offers the same masked, read-only key preview as other services. The original navigation width is retained while resource columns give addresses/references, source and status readable space.
- **Preserved 0.1.3 features:** keyless SearXNG search, multi-instance rotation, and the rebuilt Setup TUI remain attributed to [0.1.3](0.1.3.md).

## Verification evidence

- Source qualification: **608 tests / 41 files** passed.
- Source and offline isolated-installed Linux PTY qualification: **84 checks each** passed twice on the candidate. A fixture wait previously confused the `Setting` table header with the `Settings` sidebar; exact header matching resolves the reproduced race without changing runtime behavior.
- Globally installed CLI synthetic retrieval: **54 checks / 2 files** passed.
- `npm run verify:package` passed: **210 files**, no runtime install scripts; the synthetic TLS private-key fixture is excluded from the artifact.
- The final release gate is `npm run verify:release`, run against the clean reviewed release commit before publication.

No tag or npm package has been published. Live WeKnora search and Windows/macOS real-TTY behavior remain unverified. SearXNG and Web safeguards remain as described in [0.1.3](0.1.3.md); no live SearXNG qualification is implied.

## Installation

After publication, install the pinned version with:

```bash
npm install --global @arkspace/cli@0.1.4
```

Until then, use the source-development workflow in [INSTALL.md](../INSTALL.md#source-development). The generic source tarball command there is versioned `0.1.4`; a version string alone does not demonstrate npm publication.
